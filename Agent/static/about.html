에이전트 구조

웹과 터미널이 AI 엔진을 공유합니다

Render에서 웹 서버와 BridgeCLI가 함께 실행됩니다. 웹 서버는 로그인과 업무 데이터를 관리하고, BridgeCLI는 인증된 내부 API로 요청을 받아 Gemini를 호출합니다.

  3. BridgeCLI

  4. Gemini API

현재 운영 · SQLite 웹 계정과 설정은 웹 DB에, 회원 업무 기록은 계정별 작업 공간에 저장합니다. BridgeCLI에는 별도 DB가 있습니다.
전환 준비 · Supabase PostgreSQL 웹과 BridgeCLI는 각자 권한이 제한된 역할로 접속합니다. 웹의 행 수준 보안(RLS)은 계정과 작업 공간 단위로 접근을 제한합니다.

왜 BridgeCLI를 쓰나요?

웹 화면의 AI 분류와 터미널의 analyze·handover가 같은 Gemini 연결을 사용하게 하려고 만들었습니다. 모델을 바꾸거나 요청 대기열을 조정할 때 BridgeCLI 한 곳에서 관리할 수 있고, 웹 화면을 수정하는 동안에도 터미널에서 Gemini 연결을 따로 점검할 수 있습니다.

저장소 이전은 로컬 PostgreSQL에서 모의 데이터로 검증했습니다. 운영 전환은 전체 SQLite 백업 확보와 승인 이후로 보류 중입니다.
